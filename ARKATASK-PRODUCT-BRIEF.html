1. One-sentence pitch

ArkaTasks is a browser-based Italian cleaning operations app that plans who cleans which apartment each night, tracks beds/linen/extra costs in EUR, splits cleaner pay fairly, produces owner invoices-style PDF reports, sends WhatsApp day cards to cleaners, and keeps phone + laptop in sync with multi-layer backups — without requiring a native app install.

2. Problem & market

Problem

Small Italian cleaning companies serving vacation rentals / apartments typically run schedules in Excel, WhatsApp chats, and memory. Pain points:

  • Who cleans which apartment tonight / tomorrow?
  • How many single vs double beds, pillow covers, extras?
  • What to charge the property owner vs what to pay cleaners (often different amounts)?
  • How to send clear instructions to cleaners on WhatsApp?
  • How to produce a monthly owner report that looks like their familiar Italian spreadsheet (Importo, Imp.Totale, Letto Matrimoniale / Singolo)?
  • How to keep the phone and laptop agreeing without losing history when someone unticks a cleaner?
  • How not to lose the whole schedule if a phone is wiped or a free cloud DB pauses?

Ideal customer

  • Italian (or EU) cleaning / changeover companies for short-term rentals
  • 5–80 apartments
  • 2–20 cleaners
  • Owner-operator or small office staff (not large enterprise HR)
  • Already lives in WhatsApp + PDF + Excel culture

Current proof of use

Actively used in production by DClean with live operational data (properties, owners, employees, jobs, reports).

5. Feature catalog (complete)

5.1 Authentication & access control

  • Shared company username/password (default historically admin / admin; changeable in-app).
  • Session remembered per device (localStorage).
  • Settings asks for password every time (extra safety).
  • Password change syncs to Supabase app_login (plain text by design for client recovery — not bank-grade auth).
  • Sign out from sidebar.

5.2 Properties (apartments / places)

  • Create / edit / soft-archive / restore places.
  • Fields:
    • Owner (from Owners list)
    • Place name
    • Italian size: Monolocale, Bilocale, Trilocale, Quadrilocale, Quadrilocale + (legacy Doppia still loads if already saved)
    • Single beds / Double beds
    • Pillow covers per single bed / per double bed
    • Number of extra pillows
    • Owner Pay (€) — what the apartment owner is charged
    • Employee Pay (€) — pool paid to cleaners for that place (can differ from owner pay)
    • Extra cost (€) — flat add-on
    • Extra sheet cost (€) — flat add-on
    • Unit rates: Per single bed, Per double bed, Per extra pillow
  • Live Italian cost preview (“Calcolo costi”) while editing.
  • Soft-archive rules: history preserved; past/today still visible where needed; future schedule cleaned carefully.

5.3 Owners

  • Separate Owners manager (scrollable list).
  • Name + WhatsApp number (international format preferred).
  • Soft-archive when unused by active properties.
  • Powers report filter dropdown (shows all entered owners, not only those with jobs).
  • Used as WhatsApp recipients for PDF delivery.

5.4 Employees (cleaners)

  • Name, WhatsApp/phone, color code (calendar columns).
  • Soft-archive / restore.
  • Archived cleaners remain on historical jobs for reports.
  • Removed from “default schedule” template so Apply default won’t resurrect them.

5.5 Calendar / scheduling (core product)

  • Day picker (ops oriented toward tomorrow).
  • Matrix: rows = places, columns = cleaners → tick to assign one or more cleaners to a place.
  • Per-place Day details:
    • Override single/double beds for that night
    • Pillow covers rates
    • Extra pillows
    • Owner pay / Employee pay / Extra cost / Extra sheet cost
    • Sheet & pillow unit rates for that day
    • Notes for cleaners (quick suggestions: keys, towels, early/late checkout, etc.)
  • Save as default — stores tonight’s layout (including empty places) as a reusable template.
  • Apply default or Copy from another date — fills today or future only (never rewrites the past).
  • Password lock for editing schedules older than 3 days (session unlock).
  • Job snapshots freeze place name, owner, size, money fields so later property edits don’t rewrite history invoices.
  • Soft-clear (untick all) cancels the day but keeps data for revive / history — sync designed so unticks stick across devices (last-write-wins on assignments).

5.6 Dashboard

  • Today and Tomorrow panels.
  • Shows assigned jobs and places still missing cleaners.
  • WhatsApp notify cleaners: opens chats with a structured day message (places, beds, pay share, team size, notes, company branding). Batch open with delay for popup blockers.

5.7 Reports, PDF, WhatsApp to owners

  • Periods: Day / Week / Month (week starts Monday).
  • Views:
    1. Detail — line items per place/day (Italian headers)
    2. Calendar — Excel-like grid with “X” marks per day
    3. Employee — pay summaries (day = per place shares; week/month = totals)
  • Owner filter: company (all) or specific owner (all entered owners listed).
  • Only jobs that are not cancelled and have ≥1 cleaner count.
  • Owner Imp.Totale formula:
    • Importo (base owner charge)
    • + Cuscini extra (extra pillows × rate)
    • + Costo extra
    • + Costo lenzuola extra
  • PDF via jsPDF (Italian column names: DATA, APPARTAMENTI, INTERVENTO, IMPORTO, LETTO MATRIMONIALE / SINGOLO, IMP.TOTALE, etc.).
  • WhatsApp flow: download PDF → open owner chat(s) + company chat with “attach the PDF” prompt.
    Limitation: browser cannot auto-attach the PDF file; user attaches manually (standard web limitation, not WhatsApp Business API).

5.8 Money & cost engine

  • Separates what the owner pays from what cleaners earn.
  • Cleaner pay pool split across the team with cent-exact shares (no floating-point unfairness).
  • Linen calculation:
    • (single beds × per-single-bed rate) + (double beds × per-double-bed rate) + (extra pillows × per-extra-pillow rate)
    • Bed pillow covers are inventory counts, not billed.
  • Flat money add-ons: Extra cost, Extra sheet cost.
  • Day overrides can customize rates/amounts without changing the property master forever.
  • Italian UI labels in calculation panels (“Calcolo costi”, “Letti singoli”, “Letti doppi”, “Cuscini extra”, “Costo lenzuola extra”, “Costo extra”, “Totale biancheria + extra”).

5.9 Cloud sync (multi-device)

  • Free Supabase project stores one live JSON document (app_state / main).
  • Each device pastes Project URL + anon key once in Settings.
  • Auto pull/push + manual Sync.
  • Merge strategy:
    • Union of properties / employees / owners
    • Last-write-wins on job ticks/unticks and soft-deletes
    • Guards against empty cloud wiping full local data (and DB trigger protection)
    • sync_generation prevents resurrecting purged test data
  • History trail: app_state_history (advanced restore, password-locked).

5.10 Backup & disaster recovery (defense in depth)

Layer What it does
Browser working copy localStorage full app state
Device snapshots IndexedDB (~200 snapshots + last_good + daily samples)
Full cloud backups Supabase app_full_backups (~60 newest; daily when app opens)
Desktop folder Linked folder DCleanArkaTasks (Chrome/Edge File System Access API) writes daily JSON
Phone Daily JSON download to Downloads/Files
Email notice Optional FormSubmit to company email (may be summary if payload large)
Recovery banner If device looks empty but last_good exists → one-tap restore
Manual import/export Download / upload JSON
Advanced restore Password-locked local + cloud history restore

5.11 Cloud keepalive

  • Free Supabase projects can pause after inactivity (~7 days).
  • App pings cloud about every 5 days when opened to reduce surprise pauses.

5.12 Settings / company branding

  • Company name (appears on PDFs / WhatsApp brand line).
  • Company WhatsApp number.
  • All backup and sync tools live here behind password.

5.13 Soft-delete philosophy

Nothing important is hard-deleted in normal use. Archive keeps names for past reports and recovery. Designed so a busy office cannot accidentally erase history.

Tech stack

  • Frontend: Next.js 15 (static export), React 18, TypeScript, Tailwind CSS, Radix UI
  • PDF: jsPDF + autotable
  • Dates / money: date-fns; EUR with it-IT formatting
  • Backend: No custom server. Supabase as JSON document store + auth credential row
  • Hosting: Cloudflare Pages (npm run build → upload out/ folder)
  • Messaging: Opens wa.me links (not WhatsApp Business API)
  • Email backup helper: FormSubmit (free)

Data model (logical)

One AppData document containing:

  • properties[]
  • employees[]
  • owners[]
  • jobs[] (+ nested job_assignments[])
  • default_schedule map
  • settings (company name, WhatsApp, sync_generation)

Jobs snapshot operational fields per night so reports remain historically correct.

Local-first behavior

  • App is usable for local viewing/editing even if cloud is down (once loaded).
  • Sync reconciles devices when online.
  • Designed for small teams, not thousands of concurrent users.

  • Role-based access (admin vs scheduler vs viewer)
  • WhatsApp Business API auto-send with PDF attached

9. Competitive positioning (as built)

Similar categories

  • Generic workforce scheduling (When I Work, Deputy) — usually English, shift-clock oriented, not Italian apartment changeover + Imp.Totale
  • Property ops / STR tools (Guesty, Hostaway) — heavy, expensive, not focused on a small cleaning SRL’s Excel+WhatsApp workflow
  • Spreadsheets + WhatsApp — cheap but error-prone and no sync/backup discipline

Differentiation (real, in product today)

  1. Italian changeover language baked into sizes, reports, and money labels
  2. Owner charge ≠ cleaner pay, with fair team split
  3. Night grid + default schedule workflow for vacation-rental cleaning
  4. History protection (snapshots, 3-day lock, soft archive)
  5. WhatsApp-native cleaner cards + owner PDF handoff
  6. Multi-device sync + extreme backup layering on a low/no infra cost stack
  7. Install-free PWA suitable for non-technical office users
